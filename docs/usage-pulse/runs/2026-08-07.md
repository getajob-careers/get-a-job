  exception.

  `five_year_goal_role_id` set (operationally V2 — i.e., who
  progressed far enough to set a goal role), launch shows
  `has_resume_ct = 63` and `has_domain_ct = 63` of 64 — two different
  users (each count drops by exactly one), each missing one
  earlier-stage field despite completing a later step. Mechanism
  unknown — a CV-upload-skip path is documented
  (`getajob-schema.md` §5, `onboarding_cv_skipped`) as a hypothesis,
  not a confirmed cause.
- **7 unexplained (`flag_false_proxy_true`, all cohorts):**
  `onboarding_complete = false` with both proxy fields present. The
  verification query only examined flagged-complete users, so it says
  nothing about this direction. Fully open.

Not proposing a template fix yet — this needs its own `/usage`
investigation (candidate for promotion into this block per `/usage`
step 9 once resolved), not a guess written into a recurring assertion.
